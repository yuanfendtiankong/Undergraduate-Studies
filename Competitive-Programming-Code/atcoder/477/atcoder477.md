## AtCoder Beginner Contest 477

### **A - Traffic Light**

题意：我们交通灯有三种颜色（`B` (blue), `Y` (yellow), `R` (red)），他们依次次按照BYR的顺序循环往复，问我们，给定某个信号灯颜色，下个信号灯应该是什么颜色了。

```c++
#include <iostream>

using namespace std;
char ch[3] = {'B', 'Y', 'R'};
int main()
{
    char a;
    cin >> a;
    for (int i = 0; i < 3; i++)
    {
        if (a == ch[i])
        {
            cout << ch[(i + 1) % 3] << endl;
            return 0;
        }
    }
    return 0;
}
```

### **B - Standing Outliers**

题意：有N个人站在一条直线上面，每个人的编号是1-N，第i个人在的\(X_i\)位置上面，每个位置可能会有多个人，如果我们某个人的站位符合距离其余所有人的距离都大于D，那么我们就称之为被孤立的人。

```c++
#include <bits/stdc++.h>
using namespace std;
#define ll long long
int main()
{
    int n, d, ans = 0;
    cin >> n >> d;
    vector<int> a(n + 1, 0), b;
    for (int i = 1; i <= n; i++)
        cin >> a[i];
    for (int i = 1; i <= n; i++)
    {
        int flag = 0;
        for (int j = 1; j <= n; j++)
        {
            if (i != j && abs(a[i] - a[j]) < d)
                flag = 1;
        }
        if (flag == 0)
        {
            ans++;
            b.push_back(i);
        }
    }
    cout << ans << endl;
    for (auto x : b)
        cout << x << " ";

    return 0;
}
```

### **C - Range Search Query**

题意：给我们两个字符串S和T，以及Q次询问，每次询问给我们L和R，问我们在\(S_L\)到\(S_R\) 的区间内是否包含子串T。

思路：这个题最开始肯定是想到暴力吗，每次去截取\(S_L\)到\(S_R\) 然后在这个范围内直接去枚举是否包含T，但是这种算法最坏情况下会有O(QNN)，肯定是过不了的，但是我们又该如何去修改呢。我们会发现其实每次我们的截取不是必要的，我们在输入的时候已经知道我们未来要去查询的子串T了，因此我们可以直接预处理出来我们的T字符串在我们S中出现的范围，然后每次值只比较我们的[L,R]是否包含在我们的预处理的区间内，但是这样复杂度也还是O(Q*N),很明显还是平方级别的复杂度还是会超时，因此我们继续思考哪里还有优化的空间，我们会发现每次查询的时候我们没必要一个一个的去查询，因为我们预处理的时候存到数组中的区间是单调递增的，这时候我们可以使用二分查找到大于等于L的第一个范围，至此我们的时间复杂度就优化到了O(QlogN).注意我们的子串T可能比我们的S长，所以我们要特殊处理一下。

```c++
#include <bits/stdc++.h>

using namespace std;
#define endl '\n'
int main()
{
    ios::sync_with_stdio(false);
    cin.tie(0);

    int Q;
    string S, T;
    cin >> Q;
    cin >> S >> T;
    if (T.size() > S.size())
    {
        for (int i = 0; i < Q; i++)
        {
            int L, R;
            cin >> L >> R;
            cout << "No" << endl;
        }
    }
    else
    {
        vector<pair<int, int>> pos;
        for (int i = 0; i <= S.size() - T.size(); i++)
        {
            int flag = 0;
            for (int j = 0; j < T.size(); j++)
            {
                if (S[i + j] != T[j])
                    flag = 1;
            }
            if (flag == 0)
                pos.push_back({i + 1, i + (int)T.size()});
        }

        for (int i = 0; i < Q; i++)
        {
            int L, R, flag = 0;
            cin >> L >> R;
            pair<int, int> tmp = {L, -1};
            auto it = lower_bound(pos.begin(), pos.end(), tmp);

            if (it != pos.end() && it->second <= R)
                cout << "Yes" << endl;
            else
                cout << "No" << endl;
        }
    }

    return 0;
}
```

### **D - Masking Tape**

题意：给我们一排格子，从左到右编号为1, 2, 3, ..., N，每个格子的颜色用小写字母表示。最开始的时候，所有格子的颜色都是a，也都没有放置瓷砖。接下来有Q次操作，分成两种：

- `1 X` : 如果在X的位置上没有瓷砖，我们就在X的位置上铺瓷砖。如果当前位置上有瓷砖的话，我们就需要把当前位置上的瓷砖挪走。
- `2 C` : 把所有没有放置瓷砖的位置上的颜色都染成C

最后输出每个格子的颜色，不管这个格子最后有没有被瓷砖盖住。

先明确一点：**放上或者拿走瓷砖，都不会改变格子的颜色。** 瓷砖只是让格子在被盖住的期间不受染色影响。

例如只有一个格子，依次执行 `1 1 → 2 b → 1 1`，最后它仍然是a。因为染成b时它被盖住了，揭开后也不会补上之前错过的染色。

#### **思路一：倒序处理 + 两个集合**

**第一步：先从暴力想起。**

最直接的做法是维护每个格子的颜色和覆盖状态。遇到 `1 X` 就翻转状态；遇到 `2 C` 就扫描所有格子，把没有瓷砖的格子改成C。

但是一次染色最多扫描N个格子，总复杂度可能达到 `O(NQ)`。题目中N和Q都可以达到 `3 × 10^5`，所以需要减少重复处理。

**第二步：最终颜色到底取决于什么？**

固定看一个格子x，它只会在没有瓷砖时被染色。即使它经历了很多次有效染色，前面的颜色也会被后面的覆盖。

所以我们真正要找的是：

> 格子x处于未覆盖状态时，经历的最后一次染色。

如果一次有效染色都没有，它就保持初始颜色a。

**第三步：把“正序的最后一次”变成“倒序的第一次”。**

如果从后往前处理操作，第一次遇到能够作用于x的染色，就已经找到了x的最终颜色。答案一旦确定，这个格子就可以退出后续处理。

倒序时只需要恢复覆盖状态，同时确定最终颜色；不用恢复每次染色之前的颜色。

那么，我们怎么知道倒序开始时哪些格子被盖住呢？`1 X` 每出现一次，覆盖状态就翻转一次，而初始状态是未覆盖。因此：

- `1 X` 出现偶数次：最后未覆盖。
- `1 X` 出现奇数次：最后被覆盖。

读取并保存操作时，顺便统计这些翻转，就能得到最终覆盖状态。倒序遇到 `1 X` 时，再翻转一次，就恢复了这次操作之前的状态。`2 C` 不改变覆盖状态。

**第四步：只维护“还没确定答案”的格子。**

如果倒序遇到染色时仍然扫描全部N个格子，复杂度还是可能很高。于是按对话中的想法，把未确定答案的格子分成两个集合：

| 集合 | 含义 |
| --- | --- |
| `S0` | 最终颜色尚未确定，而且倒序当前时刻未覆盖 |
| `S1` | 最终颜色尚未确定，而且倒序当前时刻被覆盖 |

根据最终覆盖状态初始化两个集合，之后从第Q次操作向前处理：

- 遇到 `1 X`：如果X在 `S0` 中，就移到 `S1`；如果在 `S1` 中，就移到 `S0`。如果两边都不在，说明答案已经确定，直接跳过。
- 遇到 `2 C`：`S0` 中的格子当前都能被染色，所以把它们的最终颜色确定为C，然后清空 `S0`。`S1` 保持不变。
- 处理完后，仍未确定答案的格子保持a。

注意：**答案确定后就彻底退出两个集合，以后不能重新加入。** `S1` 里的格子只是当前被挡住了，之后倒序遇到翻转，仍然可能移到 `S0` 并找到更早的有效染色。

**第五步：用一个例子把过程串起来。**

假设N=3，正序操作依次为：`2 b → 1 2 → 2 c → 1 2 → 1 3 → 2 d`。

最终只有3号格子被覆盖，因此倒序开始时 `S0 = {1, 2}`，`S1 = {3}`。

| 倒序遇到的操作 | 处理过程 | 处理后的 `S0` | 处理后的 `S1` |
| --- | --- | --- | --- |
| `2 d` | 1、2号格子的最终颜色确定为d，退出集合 | 空 | `{3}` |
| `1 3` | 3号格子从被覆盖恢复为未覆盖 | `{3}` | 空 |
| `1 2` | 2号答案已经确定，跳过 | `{3}` | 空 |
| `2 c` | 3号格子的最终颜色确定为c，退出集合 | 空 | 空 |
| `1 2` | 2号答案已经确定，跳过 | 空 | 空 |
| `2 b` | 已没有待确定的格子 | 空 | 空 |

所以最终输出是 `ddc`。

**为什么这样做是对的？为什么不会又变成 `O(NQ)`？**

对于一个尚未确定答案的格子，倒序第一次遇到的有效染色，就是正序最后一次有效染色。更早的染色无法影响最终答案，所以确定后可以直接删除。

虽然某次染色可能遍历很多格子，但**每个格子只会被确定颜色一次**，所有染色操作遍历的格子总量最多是N。这里不是说每个格子只会进入集合一次：在答案确定之前，它仍然可能随覆盖状态在两个集合之间多次移动。

使用 `std::set` 时，插入、查找和按值删除是 `O(log N)`，总时间可以统一记为 `O((N + Q) log N)`。需要保存所有操作和两个集合，空间为 `O(N + Q)`。



#### **思路二：正序处理 + 染色版本号 + 懒更新**（比赛时的思路）

**第一步：能不能不真的逐个给格子染色？**

另一条路线仍然按输入顺序处理，但重新考虑 `2 C`：如果一个格子连续处于未覆盖状态，期间先后染成b、c、d，那么最后只需要知道它变成了d。

中间的颜色不必逐次写进数组。我们可以先记录最新染色，等需要保存或者输出这个格子的颜色时，再一次性同步。

**第二步：记录全局染色的版本。**

用两个全局变量记录：

- `cc`：目前执行过多少次类型2的染色，初始为0。每次染色都加一，即使颜色与上一次相同。
- `cur`：最近一次染色的颜色，初始为a。

于是遇到 `2 C`，只更新这两个变量，不扫描任何格子。

但仅有 `cur` 还不够。某个格子可能刚揭开瓷砖，之前的染色没有作用于它，不能立即把它看成 `cur`。所以还需要判断：**从这个格子进入本轮未覆盖状态以后，有没有发生过新的染色？**

**第三步：给每个格子记录“从哪个版本开始暴露”。**

沿用你对话里代码的含义，可以维护：

| 变量 | 含义 | 初始值 |
| --- | --- | --- |
| `st[x]` | x是否被瓷砖覆盖，0为未覆盖，1为覆盖 | 0 |
| `a[x]` | 已经保存下来的颜色，未覆盖期间可能暂时没有同步最新染色 | a |
| `last[x]` | x最近一次进入未覆盖状态时，全局染色版本是多少；对应原代码的 `c[x]` | 0 |

对于**当前未覆盖**的格子x：

- 如果 `cc == last[x]`，这一轮未覆盖期间没有发生染色，真实颜色仍然是 `a[x]`。
- 如果 `cc > last[x]`，这一轮未覆盖期间发生过染色，最新的一次一定能作用于x，真实颜色就是 `cur`。

这里 `last[x]` 记录的是进入未覆盖状态的版本，不是这个格子最后一次被染色的版本。`a[x]` 也不保证每个时刻都与真实颜色相同。

**第四步：覆盖状态变化时，该更新什么？**

遇到 `1 X` 时，分两种情况：

1. **未覆盖 → 被覆盖：先同步颜色，再盖上。**

   此时X即将停止接受后续染色。如果 `cc > last[X]`，先把 `a[X]` 保存为 `cur`；否则保留原来的 `a[X]`。然后将覆盖状态改为1。

   这样，盖上之后保存的就是这一刻的真实颜色。以后即使全局继续染色，也不会改变它。

2. **被覆盖 → 未覆盖：保留颜色，记录新的起点。**

   将覆盖状态改为0，并把 `last[X]` 记为当前的 `cc`。`a[X]` 不变。

   因为揭开本身不改颜色，而且被盖住期间的染色都应该忽略。记录当前版本后，只有将来新增的染色才会被认为对X有效。

**第五步：最后输出时，再同步仍然暴露着的格子。**

| 最终状态 | 应输出的颜色 |
| --- | --- |
| 被覆盖 | `a[x]`，因为盖上前已经同步过 |
| 未覆盖，且 `cc > last[x]` | `cur`，因为本轮暴露期间有新的染色 |
| 未覆盖，且 `cc == last[x]` | `a[x]`，因为本轮暴露期间没有染色 |

**用同一个例子理解版本号。**

沿用上面的操作，只看2号格子，省略不影响它的 `1 3`：

| 步骤 | `cc / cur` | 2号格子是否覆盖 | `last[2]` | 保存的 `a[2]` | 真实颜色 |
| --- | --- | --- | --- | --- | --- |
| 初始 | `0 / a` | 未覆盖 | 0 | a | a |
| `2 b` | `1 / b` | 未覆盖 | 0 | a，暂时不更新 | b |
| `1 2` | `1 / b` | 覆盖 | 0 | 先同步为b | b |
| `2 c` | `2 / c` | 覆盖 | 0 | b | b |
| `1 2` | `2 / c` | 未覆盖 | 2 | b，揭开时保留 | b |
| `2 d` | `3 / d` | 未覆盖 | 2 | b，暂时不更新 | d |

最终2号格子未覆盖，且 `3 > 2`，所以输出d。尤其注意第二次 `1 2`：此时虽然 `cur` 是c，但刚揭开的格子仍然是b，记录 `last[2] = 2` 正是为了排除之前无效的染色。

**为什么这样做是对的？**

被覆盖时，`a[x]` 保存了盖上前的真实颜色，后续染色不会作用于它。未覆盖时，`last[x]` 划出了这一轮暴露的起点：若版本没有增加，颜色保持不变；若增加了，最近一次全局染色就在这段暴露期间，直接取 `cur` 即可。

盖上前同步、揭开时记录版本，正好让这两个规则始终成立。这就是“懒更新”：暂时不把每次染色写入各个格子，在盖上或最终输出时再取得正确颜色。

每次操作只做常数次比较和赋值，最后再遍历N个格子，总时间为 `O(N + Q)`，空间为 `O(N)`，可以边读入边处理，不用保存操作历史。

**代码：**

```c++
#include <bits/stdc++.h>

using namespace std;

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(0);

    int n, q;
    cin >> n >> q;
    vector<char> a(n + 1, 'a');
    vector<int> st(n + 1, 0), last(n + 1, 0);
    int cc = 0;
    char cur = 'a';

    for (int i = 0; i < q; i++)
    {
        int op;
        cin >> op;
        if (op == 1)
        {
            int x;
            cin >> x;
            if (!st[x])
            {
                if (cc > last[x])
                    a[x] = cur;

                st[x] = 1;
            }
            else
            {
                st[x] = 0;
                last[x] = cc;
            }
        }
        else
        {
            char b;
            cin >> b;
            cur = b;
            cc++;
        }
    }

    for (int i = 1; i < a.size(); i++)
    {
        if (st[i])
            cout << a[i];
        else
        {
            if (cc > last[i])
                cout << cur;
            else
                cout << a[i];
        }
    }

    return 0;
}
```
