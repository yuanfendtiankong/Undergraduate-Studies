### **A - Chocolate Bar Count**

**题意**

一块巧克力有 $30$ 行、$30$ 列。去掉最下面的 $B$ 行，再去掉最右边的 $R$ 列，问还剩多少块。[原题](https://atcoder.jp/contests/abc484/tasks/abc484_a)

**思路**

代码从总数 $900$ 开始，减掉底下和右边去掉的格子。直接减去 $30B$ 和 $30R$ 时，右下角的 $B\times R$ 个格子被减了两次，所以要加回来。也可以直接看剩下的行列数，答案就是 $(30-B)(30-R)$，展开后与代码里的式子相同。

时间复杂度和空间复杂度均为 `O(1)`。

```c++
#include <bits/stdc++.h>

using namespace std;

int main()
{
    int a, b;
    cin >> a >> b;
    cout << 900 - (a + b) * 30 + a * b << endl;

    return 0;
}
```

### **B - Nineball**

**题意**

桌上还剩 $K$ 颗球。如果 9 号球已经不在桌上，游戏结束，输出 `-1`。否则输出桌上编号最小的球。[原题](https://atcoder.jp/contests/abc484/tasks/abc484_b)

**思路**

读入时同时做两件事。遇到 9 号球就把 `flag` 设为 1，每读到一颗球就用 `min` 更新最小编号 `ans`。`ans` 的初始值 `1024` 大于所有球号，读入第一颗球时就会被更新。最后根据 `flag` 输出。如果桌上只剩 9 号球，最小编号也是 9。

时间复杂度为 `O(K)`，空间复杂度为 `O(1)`。

```c++
#include <bits/stdc++.h>

using namespace std;

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(0);

    int n, flag = 0, ans = 1024;
    cin >> n;
    for (int i = 0; i < n; i++)
    {
        int x;
        cin >> x;
        if (x == 9)
            flag = 1;
        ans = min(ans, x);
    }
    if (!flag)
        cout << -1 << endl;
    else
        cout << ans << endl;
    return 0;
}
```

### **C - Move One Card**

**题意**

给定两个长度为 $N$ 的序列 $A$ 和 $B$。从 $A$ 中取出一个元素，再插回任意位置，问操作一次后能不能得到 $B$。允许放回原位，所以 $A=B$ 时也可以输出 `Yes`。[原题](https://atcoder.jp/contests/abc484/tasks/abc484_c)

**最开始的思路和卡点**

我一开始想找第一个满足 `a[i] != b[i]` 的位置，再比较 `a[i] == b[i+1]` 和 `a[i+1] == b[i]`。

- `a[i] == b[i+1]` 符合把后面的某个元素移到 `i` 的情况。这时 `a[i]` 被挤到右边一格。
- `a[i+1] == b[i]` 符合把当前位置的元素移到后面的情况。这时 `a[i+1]` 补到左边一格。

这两个比较只检查了开头的一组对应关系。还需要确定**应该比较到哪里**，以及**被取出的元素能不能接到另一端**。我最早用 `pos` 记录不匹配的位置，但循环中每遇到一次不匹配就覆盖 `pos`，最后留下的是最后一个不匹配的位置。补题时把两个端点分别记成 `l` 和 `r`。

另一个卡点在输出。最初写成某个方向一失败就输出 `No`，这样会跳过另一种可能。比如 `A = [1, 2, 1, 2, 2]`、`B = [2, 1, 2, 2, 1]`，第一个不匹配的位置上两种相邻比较都成立。把右端的 2 移到开头，会得到 `[2, 1, 2, 1, 2]`，这一种失败。把开头的 1 移到末尾，就能得到 $B$。所以代码用局部变量 `ans` 记录一个方向是否通过，用 `flag` 记录是否存在通过的方向，最后统一输出一次。

**为什么只检查首尾不匹配的位置？**

取出一个元素再插入，相当于把它经过的整段区间循环移动一格。假设有一个可行区间 $[L,R]$。因为区间以外的位置不变，所以 $[L,R]$ 必须包含第一个和最后一个不匹配的位置 $l$、$r$。接下来还要证明，可行区间多出来的部分可以裁掉。

以把 `a[R]` 移到 `L` 为例。操作后有 `b[L] == a[R]`，区间内其余元素向右挪一格。

- 如果左端本来相同，即 `a[L] == b[L]`，那么 `a[L] == a[R]`。原操作会把 `a[L]` 放到 `L+1`。改成只移动 $[L+1,R]$ 时，会直接把值相同的 `a[R]` 放到 `L+1`，所以结果一样。
- 如果右端本来相同，即 `a[R] == b[R]`，那么 `a[R] == a[R-1]`。改成只移动 $[L,R-1]$ 时，移到 `L` 的是 `a[R-1]`，和原来移过去的值相同，结果也一样。

把首元素移到尾部的情况可以把两个序列倒过来，用同样的论证。这样每次都能去掉一个仍相同的端点，直到只剩 $[l,r]$。所以只要有解，一定能用这段区间得到 $B$。[C 题官方题解](https://atcoder.jp/contests/abc484/editorial/29001)

**怎么实现**

先从左右两端跳过相同的位置。若 `l > n`，说明两个序列原本就相同。否则分别检查下面两种方向。

| 操作 | 被取出的元素 | 区间内其他元素 |
| --- | --- | --- |
| 把 `a[r]` 移到 `l` | `a[r] == b[l]` | 对每个 `l <= i < r`，检查 `a[i] == b[i+1]` |
| 把 `a[l]` 移到 `r` | `a[l] == b[r]` | 对每个 `l < i <= r`，检查 `a[i] == b[i-1]` |

例如样例 1 中，`A = [1, 4, 1, 4, 2, 1]`，`B = [1, 4, 1, 1, 4, 2]`。首尾不匹配的位置是 `l = 4`、`r = 6`。把末尾的 1 放到第 4 位，区间 `[4, 2, 1]` 就变成 `[1, 4, 2]`，对应表里的第一种操作。

找区间和检查两个方向都只需要顺序遍历，时间复杂度为 `O(N)`。两个数组占 `O(N)` 空间，除此以外只使用 `O(1)` 额外空间。

```c++
#include <bits/stdc++.h>
using namespace std;

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(0);

    int n;
    cin >> n;
    vector<int> a(n + 1), b(n + 1);
    for (int i = 1; i <= n; i++)
        cin >> a[i];
    for (int i = 1; i <= n; i++)
        cin >> b[i];

    int l = 1, r = n;
    while (l <= n && a[l] == b[l])
        l++;
    while (r >= 1 && a[r] == b[r])
        r--;

    //cout << l << " " << r << endl;

    if (l > n)
    {
        cout << "Yes" << endl;
        return 0;
    }

    // a[r]=b[l] a[i]=b[i+1]
    bool flag = false;
    if (a[r] == b[l])
    {
        bool ans = true;
        for (int i = l; i < r; i++)
            if (a[i] != b[i + 1])
                ans = false;
        if (ans)
            flag = true;
    }
    // a[l]= b[r] a[i+1] = b[i]
    if (a[l] == b[r])
    {
        bool ans = true;
        for (int i = l + 1; i <= r; i++)
            if (a[i] != b[i - 1])
                ans = false;
        if (ans)
            flag = true;
    }

    cout << (flag ? "Yes" : "No") << '\n';

    return 0;
}
```

### **D - Move One Card Left**

**题意**

给定一个长度为 $N$ 的序列 $A$。取出第 $r$ 个元素，插入第 $l$ 个位置，要求 $1\le l\le r\le N$。操作恰好一次，求能得到多少个不同的序列。不同的操作如果得到同一个序列，只算一次。[原题](https://atcoder.jp/contests/abc484/tasks/abc484_d)

**卡点**

固定右端 `r` 后，可以选它左边的位置作为插入点。但直接累加插入点的数量会重数。例如 `A = [1, 2, 1, 1]`，把第 4 个元素插到第 1 位，或者把第 3 个元素插到第 2 位，都得到 `[1, 1, 2, 1]`。原序列也会被多次得到，比如任选一个元素取出再放回原位。

为什么 `a[r] == a[r-1]` 时要跳过这个右端？为什么右端通过后，还要从左边的位置里扣掉所有与 `a[r]` 相同的值？这两个条件分别来自移动后**右端和左端是否真的发生变化**。

**1. 每个变化后的序列只保留最短区间**

把 `a[r]` 移到 `l`，相当于把 $[l,r]$ 循环右移一格。设结果为 $B$。如果 $B=A$，单独计为一种，所以代码初始化 `ans = 1`。

如果 $B\ne A$，记 $p$、$q$ 为 $A$ 和 $B$ 首尾不匹配的位置。借用 C 题的裁剪结论，只要移动区间的某个端点没有变化，就可以把它裁掉，最后一定能用 $[p,q]$ 得到同一个 $B$。在上面的例子中，移动 $[1,4]$ 虽然能得到 `[1, 1, 2, 1]`，实际上只有第 2、3 位变了，所以只保留 $[2,3]$。

只统计**左右端点都发生变化**的区间，就能保证以下两点。

- **不漏数。** 每个 $B\ne A$ 都能裁到 $[p,q]$，而这两个端点一定发生了变化。
- **不重数。** 区间以外保持不变。如果 $l$ 和 $r$ 都变了，就能从结果里唯一找回 `l = p`、`r = q`。因此两个不同的区间不会得到同一个 $B$。D 题只允许把右端元素移到左端，所以同一个区间也只有一种结果。

**2. 把端点发生变化写成判断条件**

对于 $l<r$，移动后的左端是原来的 `a[r]`，右端是原来的 `a[r-1]`。

| 位置 | 原来的值 | 移动后的值 | 要求 |
| --- | --- | --- | --- |
| `l` | `a[l]` | `a[r]` | `a[l] != a[r]` |
| `r` | `a[r]` | `a[r-1]` | `a[r] != a[r-1]` |

因此，若 `a[r] == a[r-1]`，以 `r` 结尾的区间右端都不会改变，全部跳过。若两者不同，只要数一数 `r` 左侧有多少个位置满足 `a[l] != a[r]`。官方题解也是用两个端点确定唯一的区间。[D 题官方题解](https://atcoder.jp/contests/abc484/editorial/29002)

**3. 用前缀计数求出每个右端的贡献**

代码用 `i` 表示右端。刚读入 `a[i]` 时，`cnt[x]` 记录的是值 `x` 在前 `i-1` 个位置中出现的次数。所以右端变化时，合法的左端数量就是 `i - 1 - cnt[a[i]]`。必须先算贡献，再执行 `cnt[a[i]]++`。即使这次的右端被跳过，当前值也要加入计数，因为它仍然是后面位置的前缀元素。

继续用 `A = [1, 2, 1, 1]` 举例。

| 右端 `i` | 当前元素 | 新增结果数 |
| --- | --- | --- |
| 1 | 1 | 左边没有位置，贡献 0 |
| 2 | 2 | 左边有 1 个位置，没有相同的值，贡献 1 |
| 3 | 1 | 左边有 2 个位置，其中 1 个值也是 1，贡献 1 |
| 4 | 1 | 与前一项相同，贡献 0 |

再加上原序列这一种，总共 $1+0+1+1+0=3$ 种。代码里的 `a[0] = 0`，题目元素都是正数，所以读到第一项时会进入判断，但左边没有位置，贡献仍然是 0。$N$ 最大为 $2\times10^5$，当所有元素互不相同时，答案为 $1+N(N-1)/2$，需要用 `long long`。

每个位置读入时处理一次，时间复杂度为 `O(N)`，空间复杂度为 `O(N)`。

```c++
#include <bits/stdc++.h>

using namespace std;
#define ll long long
#define endl '\n'
int main()
{
    ios::sync_with_stdio(false);
    cin.tie(0);

    int n;
    cin >> n;
    vector<int> a(n + 1, 0);
    vector<int> cnt(n + 1, 0);

    ll ans = 1;
    for (int i = 1; i <= n; i++)
    {
        cin >> a[i];

        if (a[i] != a[i - 1])
            ans += (i - 1 - cnt[a[i]]);
        cnt[a[i]]++;
    }
    cout << ans << endl;

    return 0;
}
```

#### 拓展

C 题给了目标序列 $B$，首尾不匹配的位置直接告诉我们该检查哪个区间，再试两个方向。D 题没有给出 $B$，就反过来数那些移动后两端都会变化的区间。因为方向已经固定，每个这样的区间正好对应一个不同的结果。
